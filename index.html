Lab Assignment: Connect an Arduino to the Cloud with Blynk

Wire up sensors, program an Arduino Uno WiFi Rev 2 and watch live readings on a Blynk dashboard.

Lesson 1 – Industrial IoT and this lab

In this lesson: you see why connected devices matter in industry and what you will build by the end of the course.

The Arduino Uno WiFi Rev 2 is a small board with a microcontroller, an onboard motion sensor (IMU) and a Wi-Fi/Bluetooth module. Paired with Blynk, a cloud dashboard, it mimics the building blocks of an Industrial Internet of Things (IIoT) system: devices that sense, share data and take commands remotely.

Sensing & monitoring

Predictive maintenance: a temperature sensor on a motor alerts technicians before it fails.

Asset tracking & security: motion sensors and IMUs track valuable assets or detect unauthorised access.

Connectivity & control

Remote management: the Wi-Fi module sends readings to the cloud. A dashboard lets managers view data from many devices and send commands back, such as switching off a pump.

By the end of this assignment you can

  • connect hardware to the Arduino Uno,
  • flash a program into the Arduino Uno,
  • connect the Arduino Uno to Blynk.

Parts list

Lab resources

You will need the Lab Resources folder (it contains the E118Lab sketch and the Arduino IDE installer). Fully unzip it before use. Download location: to be added.

Key takeaways

  • Industrial IoT (IIoT) links sensors and actuators on machines, farms and buildings to the cloud so people can monitor and control them remotely.
  • Your kit mirrors this: temperature/humidity and motion sensors for sensing, LEDs and a buzzer as actuators, and a Wi-Fi board that talks to the Blynk cloud.
  • You will finish with a working system you can read and control from a web dashboard.

Lesson 2 – Assemble the hardware

In this lesson: you connect the sensors, buzzer and screen to the Arduino shield, and learn the safety rules for powered electronics.

Everything is wired while the board is unpowered. Wrong connections on a powered board can destroy parts, so USB goes in last and only on the Arduino side for now.

Before you start

Connect every component before plugging the USB cable into your laptop. The USB cable powers the board, and wrongly connected parts can burn out. If you smell burning, hear a bang or see smoke, unplug the USB cable immediately. Never touch exposed metal on a powered board.

  1. Check every component for visible damage. Tell your lecturer if anything is damaged.

  2. Look at the cable connectors: they only fit when the correct sides line up. Do not force them; you will bend the pins.

  3. Connect the temperature & humidity sensor, the LEDs & buzzer and the motion sensor to the sockets labelled for them on the shield.

  4. Plug in the 0.96" OLED screen. Check it faces the correct orientation shown.

  5. Connect the USB cable to the Arduino only. Do not plug the other end into your laptop yet.

Key takeaways

  • Connect all components before the USB cable touches your laptop.
  • Connectors fit one way only; never force them.
  • The OLED screen must face the correct orientation.
  • Unplug at once if you smell burning, hear a bang or see smoke.

Lesson 3 – Install Arduino IDE

In this lesson: you install the software used to write code and send (flash) it to the Arduino.

The Arduino IDE is the tool that connects your laptop to the board. If you installed it in an earlier module, updating it is enough.

Already installed?

If you installed Arduino IDE in a previous module, skip this lesson, or just update to the latest version.

  1. Download arduino-ide_2.3.10_Windows_64bit from arduino.cc (Windows 10 or newer, 64-bit) and save it to Downloads. If the school network blocks the site, install “Arduino IDE” from the Microsoft Store, or use the installer in your fully unzipped Lab Resources folder.

  2. Run the installer. Click I Agree, choose Only for me, click Next, then Install. When it finishes, click Finish to launch the IDE.

Key takeaways

  • The Arduino IDE lets your laptop program the board over USB.
  • If arduino.cc is blocked, use the Microsoft Store or the installer in the Lab Resources folder.
  • Install “Only for me” and launch the IDE when setup finishes.

Lesson 4 – Set up the IDE for the board

In this lesson: you teach the IDE about your board and add the libraries the lab code depends on.

A board package tells the IDE how to build code for the Uno WiFi Rev 2. Libraries are ready-made code for the sensors, screen, Wi-Fi and Blynk, so you don’t write that low-level code yourself.

Update pop-ups

Whenever the IDE offers library updates, click Install All. Skipping them causes missing-library errors when you compile.

  1. Open the Arduino IDE.

  2. Install the board package: Tools > Board > Boards Manager. Search “rev2” and install the latest Arduino megaAVR Boards, then close the panel.

  3. Select the board: Tools > Board > Arduino megaAVR Boards > Arduino Uno WiFi Rev2.

  4. The board name now appears in the toolbar.

  5. Open the Library Manager from the left panel (or Sketch > Include Library > Manage Libraries…).

  6. Search Adafruit SHT31 Library, pick the latest 2.2.x and install it. Then click Install All if asked.

  7. Check that Adafruit BusIO (latest 1.16.x) is installed.

  8. Install WiFiNINA (latest 1.8.x).

  9. Install Blynk (latest 1.3.x).

  10. Search “timekeeping functionality” and install Time by Michael Margolis (latest 1.6.x).

  11. Search “tinygsm small” and install TinyGSM (latest 0.12.x).

  12. Install SSD1306Ascii (latest 1.3.x).

Key takeaways

  • Install the Arduino megaAVR Boards package, then select Arduino Uno WiFi Rev2.
  • Install seven libraries: SHT31, BusIO, WiFiNINA, Blynk, Time, TinyGSM and SSD1306Ascii.
  • Always choose Install All on update pop-ups, or compiling will fail with missing libraries.

Lesson 5 – Build the Blynk dashboard

In this lesson: you create the cloud side of the system: a template, its datastreams, a web dashboard and a device.

A template is a digital model of your device. Datastreams are the values it sends or receives, each tied to a virtual pin (V0, V2, V3, V6). The dashboard widgets display or control those datastreams. Creating the device gives you an auth token that links the real board to this setup.

Before you begin

Use a different laptop from the one where you set up the IDE if you can. Blynk may be blocked on the school Wi-Fi, so use your own mobile data or hotspot. Open the activation email in your laptop browser, not your phone, or you will be pushed to install the Blynk app.

  1. Go to blynk.io, click Start Free and register.

  2. Activate your account from the email, then log in.

  3. You arrive at the Blynk console home page.

  4. Click Developer Zone > My Templates > + New Template.

  5. Fill in: Name E118IoT, Hardware Arduino, Connection Type WiFi, Description E118 IoT. Click Done.

  6. Click Save (top right) as a back-up.

  7. Click Edit at the top right.

  8. Click Set Up Datastreams.

  9. Click + Create New.

  10. Name the datastream Temperature and press Enter. Blynk suggests virtual pin details for common names.

  11. Set the Virtual Pin, Data Type, Min/Max and Unit as shown (Temperature: V2, Integer, 0 to 256, Celsius). Click Save.

  12. Remember to click Save (bottom right).

  13. Add three more datastreams with New Datastream, using the table below.

    S/NNamePinData typeUnitsMinMaxRemarks
    1TemperatureV2IntegerCelsius, °C0256Done above
    2HumidityV6IntegerPercentage, %0100
    3BuzzerV0IntegerNone01No auto pop-up
    4StringV3StringNone

  14. Check all four datastreams look right, then click Save.

  15. Go to Developer Zone, open the E118IoT template and get ready to build the Web Dashboard.

  16. Make sure Set Up Datastreams shows as done, then click Edit.

  17. Click Set up the Web Dashboard.

  18. Drag a Switch and a Label onto the canvas. Use the small arrow at a widget’s bottom-right corner to resize it.

  19. Hover over the Switch widget and click the gear icon.

  20. Set Title to Buzzer and Datastream to Buzzer (V0), then click Save.

  21. Use Label widgets for Temperature, Humidity and String. For Temperature, choose datastream Temperature (V2) and click Save.

  22. Add another Label for Humidity: datastream Humidity (V6), then Save.

  23. Add another Label for String: datastream String (V3), then Save.

  24. Your dashboard should look like this. Click Save at the top right.

  25. Go back to Templates and select E118IoT.

  26. Click Edit, then Add First Device.

  27. Name the device E118IoT and click Create.

  28. Do not miss this step. In the pop-up, hover at the top right to show the copy icon and click it. Paste the three #define lines into Notepad or Word. You need them later to link the Arduino to Blynk.

    Keep it private

    The third line is your device’s auth token. Don’t post it or share screenshots of it.

Key takeaways

  • Template E118IoT with four datastreams: Temperature (V2), Humidity (V6), Buzzer (V0) and String (V3).
  • A Switch widget controls the buzzer; Label widgets show temperature, humidity and the motion string.
  • Copy the three #define lines from the new device pop-up, and keep the token private.

Lesson 6 – Connect the Arduino to Blynk

In this lesson: you load the lab sketch, enter your Blynk and Wi-Fi details, upload it and test the whole system.

The sketch reads the sensors, shows values on the OLED and sends them to Blynk over your hotspot. The secrets.h file holds your device details so they stay separate from the main code.

  1. Open File > Open and choose E118Lab.ino in the E118Lab folder of your fully unzipped Lab Resources.

  2. The sketch opens in the IDE.

  3. Double-check the connections, then plug the USB cable into your laptop. The board powers up and the OLED shows “System ON / Waiting…”.

  4. Choose Tools > Port > COM X (Arduino Uno WiFi Rev2). The number X depends on your laptop.

  5. Select Tools > Get Board Info to test the connection.

  6. If it works, the Board Info box appears. Click OK.

  7. Open the secrets.h tab next to E118Lab.ino. Replace the first three #define lines with the ones you copied in step 47. If you lost them, open Device Info in Blynk.

  8. Turn on your phone hotspot and set WIFI_SSID and WIFI_PASS to its name and password (use a temporary password for this lab). Press Ctrl+S to save.

    Hotspot settings

    Apple devices: turn on Maximise Compatibility. Android: select the 2.4 GHz band.

  9. Click Verify and make sure the status bar shows no errors. Don’t upload yet.

  10. Click Upload and make sure there are no errors.

  11. Open the Serial Monitor.

  12. Set the baud rate to 74880 baud.

  13. If the upload fails, hold the Arduino’s reset button for about 3 seconds.

  14. When it works, the OLED shows temperature and humidity.

  15. The readings also appear on the Blynk dashboard. Check the device status says Online.

  16. Test everything: slide the Buzzer switch, put a finger on the temperature sensor and watch both displays, then move the board to see the motion status change.

  17. Congratulations! You built an IoT sensor system. Try powering it from a portable battery, keeping your hotspot nearby. Then take a group photo with your working setup.

  18. Reset the board to default code: unplug it, create a new sketch (File > New), replace its contents with the blank code below, reconnect the board, select the board and port, and click Upload.

    void setup() {
  // put your setup code here, to run once:
}

void loop() {
  // put your main code here, to run repeatedly:
}

Key takeaways

  • Select the correct board and COM port, and confirm with Get Board Info.
  • Put your Blynk lines and hotspot name/password in secrets.h, then Verify before Upload.
  • Use 74880 baud in the Serial Monitor, and reset the board if an upload fails.
  • Success means the OLED shows readings and Blynk shows the device Online.
  • Finish by uploading blank code to reset the board.
